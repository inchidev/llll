# L4 0.2.16

This release fixes the Cloudflare Factory image published in 0.2.15 and preserves setup choices through authorization. Landing, Shell, installer, Server, portable runtime and Docs share **0.2.16**. Existing customer Servers stay pinned until their operator chooses an update.

- Factory image layers are compressed exactly once. The builder handles both classic Docker tar exports and already-compressed containerd exports. Before publication, the release verifies the compressed descriptors, readable tar contents and each uncompressed `diff_id` against the image config. The double-gzipped 0.2.15 image fails this check even when its download checksums match.
- The Factory installer keeps the selected compute size, command timeout and process limit across the Cloudflare redirect in the same browser tab, scoped to the selected account and Worker. The resource summary follows the chosen size.
- GitHub App setup explains how to recover when GitHub sudo/MFA loses the submitted manifest. Preparing again checks for a completed connection first and generates fresh setup state, without retrying a credential exchange or automatically creating another App.

No Server SQL migration is required. Durable Object migration `v5-factory-executor` is unchanged. Published releases and earlier migrations remain immutable.

For a Cloudflare Server whose Factory activation failed on 0.2.15: back up and update the Server to 0.2.16, provision Factory again through `/create` to select the corrected published image, then activate it in Settings → Repositories. Keep any existing Task source and backup destinations. Provisioning does not upgrade the Cloudflare plan.
