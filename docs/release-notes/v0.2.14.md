# L4 0.2.14

Software Factory fixes the agent-facing failures reported in #339 and adds optional Cloudflare Containers/Artifacts and a versioned VPS executor installer from #340. Landing, Shell, installer, Server, portable runtime and Docs share **0.2.14**. Existing customer Servers stay pinned until their operator chooses an update.

- Exact tool-name discovery now finds every permitted tool. Repository, coding and Compute Node searches surface Factory tools. Advertised object arguments are normalized per operation, invalid inputs name their fields, and every Factory call—including validation failures—has a private Run audit.
- Runs wait while approval or execution is outstanding. A coding Run without completed operations cannot move its Task to Review. New attempts receive bounded, Task/Agent/initiator/repository-scoped receipts. Project admission names the missing Read projects permission; failed message admission produces a visible safe notice. Model transport retries transient failures; publication approval returns before its background broker work finishes.
- Cloudflare Factory is an explicitly authorized paid addition. The installer uploads checksum-verified, immutable image layers, adds optional Containers/Artifacts bindings to the existing Server, and preserves UUID, database, secrets, Git connections and files. Basic Free/KV installs allocate no paid Factory resources; R2 remains independent. Compute size, command timeout and process limits are chosen during activation. No plan upgrade or paid fallback is performed.
- Each Cloud Task operation starts a released image, restores acknowledged source, runs as UID/GID 1000, and checkpoints Git history plus staged, unstaged and untracked source before acknowledging its receipt. Credentials remain in the outbound Worker and are limited to the current source read or private Task repo. The root idle supervisor survives termination of Task processes. Idle containers stop after each checkpoint; dependencies/build output and process memory are disposable. Interrupted/uncertain effects never replay automatically.
- VPS operators can opt into Factory on fresh installation or run `llll factory enable --trust-shared-kernel`. Verified release assets include Node, the Compute Node and an immutable workspace image; no source build or registry is needed. Preflight checks capacity and actual loop/mount support. A private systemd service pairs after Owner creation. Restart, disable, source/receipt backup and service removal preserve source unless separately released. Existing image changes fail before stopping the pinned service and require explicit replacement for new Tasks.
- Setup and review show availability, provider limits, checkpoint recovery and retained code export. GitHub App setup defaults to personal ownership, new Roles start with no grants, a separate Factory role preset includes Read projects, and idle Agents appear available. Existing original-repository draft PR, exact-head CI/Preview and same-PR repair semantics remain authoritative.

No Server SQL migration is required. The exported optional executor class appends Durable Object migration `v5-factory-executor`; its Container application/bindings are enabled only by paid activation. Published releases and earlier migrations remain immutable.

Local evidence includes unit/security fixtures, immutable release/installer checks, actual Docker Git Smart HTTP checkpoint/replacement tests and root-supervisor cleanup. These do not certify live Cloudflare provisioning, fresh public VPS HTTPS/systemd/quota/reboot, a real restricted GitHub App/model-provider run, or mobile acceptance. As requested, Grok performs those fresh-install and Agent flows after publication using [the acceptance procedure](../software-factory-acceptance.md); record exact release/commit and real provider links. Existing foundation trackers remain open until their own acceptance is demonstrated.
