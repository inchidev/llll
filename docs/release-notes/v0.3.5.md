# L4 0.3.5

This release publishes the Server as a Docker image for Coolify and Docker Compose, and gives a Server's own installed app notifications, an unread badge and its own name and icon. Landing, Shell, installer, Server, portable runtime and Docs share **0.3.5**. It stays on the `server-v2` lineage and adds no migrations. Customer Servers update only when their operator chooses an update.

## Docker image and Coolify

- Stable releases are published as `ghcr.io/inchidev/llll` for `linux/amd64` and `linux/arm64`, tagged with the exact version (`0.3.5`), its minor line (`0.3`) and `latest`. Prereleases are not published as images.
- The Coolify template runs that image. It uses `latest` unless `LLLL_VERSION` pins a version. To update, redeploy or change the version; Coolify owns the domain and TLS.
- Migrations only go forward. A container refuses to start an image older than the release that last migrated its data, before it changes anything.
- On a Docker Server, Settings → Deployment → Updates says updates are managed where the Server is deployed and shows when a newer stable release exists.

## Installed Server app

- A Server's installed web app gets notifications while it is closed, and its icon shows the unread conversation count.
- The Server creates its push keys automatically and keeps keys an operator provided. Notifications are turned on from a tap or click.
- The installed app and link previews use the Server's own name and icon.

## Update to this release

A Cloudflare Server that keeps Cloudflare access updates from Settings → Deployment → Updates by itself. A Docker Server updates by its image tag in Coolify or Docker Compose; the VPS installer uses `llll upgrade`.
