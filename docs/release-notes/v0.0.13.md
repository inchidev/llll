# L4 0.0.13

A Server on L4 Cloud keeps its Projects' code inside L4, and a product built on L4 can start a game there for its creator. This release adds one migration, `0008`, additive. Take the pre-update backup as usual.

## Software Factory

- **Repositories in L4 on hosted Servers.** A Server on L4 Cloud now has its own Artifacts namespace from its installer, so a Project can create its repository inside L4 there too, with no GitHub or Gitea account: one repository per Project, a branch per Task, versions as tags on `main`, review and merge in the Task ([ADR 0013](https://github.com/inchidev/llll/blob/main/docs/adr/0013-artifacts-git-provider.md)). Deleting the Server deletes its repositories. A hosted Server made before this release says it gets repositories with its next update.
- **Games from a partner product.** L4 Cloud's partner AfterPrompt can create a game's Project with its repository, give the Server's Agent a Task with the creator's words, links and files, pass the creator's messages to it and read its state, branch and commits back ([ADR 0012](https://github.com/inchidev/llll/blob/main/docs/adr/0012-server-creation.md)). Each call acts as the Member the partner's identity names. A friend the creator invited starts games too: the Owner makes the Project and the friend gets Developer access to it only. A repeated request gets its first answer.

## Updating

- The update applies migration `0008`, which adds the table `cloud_relay_requests`. It only adds; nothing is dropped.
- A Server in your own Cloudflare account changes nothing: its repositories in L4 already came from Compute. The relay `/.llll/cloud/*` gains actions that only a Server with `LLLL_RUNTIME=cloud` answers; every other Server keeps answering 404 there.
- Hosted Servers are not updated in place yet: the namespace binding and the new actions reach only Servers created from this release or later.
