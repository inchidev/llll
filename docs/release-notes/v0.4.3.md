# L4 0.4.3

The server connection page is reorganized for calmer flows, provisioning failures are visible on the card, and a freshly deployed workspace is verified from the browser because Cloudflare blocks worker-to-worker fetches to same-account workers.dev origins.

## Changes

- Servers across installations are grouped into separate Servers, Settings and Account tabs, each action carries its own loading state, and the tab defaults follow your sign-in state.
- Failed server cards show the provisioning reason, and opening is disabled until the server is ready.
- Server provisioning no longer verifies workspace health from inside the installation worker: Cloudflare error 1042 blocks fetches to `*.workers.dev` on the same account, so verification polled 404 forever while the deployment itself succeeded. The server runtime answers `/api/setup/health` with CORS, the connections page polls it and confirms, and a provisioning server is failed after ten minutes of silence.
- Server updates through an installation skip the same in-worker verification and rely on the browser check too.
