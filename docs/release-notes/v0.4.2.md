# L4 0.4.2

Browser installer hardening from the first live deployment attempt: the Workers Admin role scope is now requested during Cloudflare authorization, missing rights are named at the start of deployment, and Cloudflare API errors always carry the upstream reason.

## Changes

- Request `workers-scripts.admin` on the Cloudflare consent screen: provisioning must create a worker, and the previously requested Editor role cannot. This was the root cause of `assets-upload-session` failing with a bare 403 during a live install.
- `/api/deploy/start` probes Workers access and refuses before creating any resource, with reconnect-or-admin guidance, instead of failing two phases later.
- The assets upload 403 now names the missing Workers edit rights; Cloudflare API errors attach their HTTP status so callers can discriminate.
- Deploy method tabs hide once Cloudflare is connected, and the Cloudflare section stays pinned while the flow is committed.
- Installation workers deploy with `auto-trailing-slash` asset handling, matching the portal's refresh fix.
