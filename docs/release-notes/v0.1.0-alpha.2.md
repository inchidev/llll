# L4 0.1.0-alpha.2

Second developer alpha for independent community Servers, with local Instance accounts and separately isolated Server data. This release includes the changes accumulated after alpha.1 and introduces the coordinated release-to-production pipeline.

- Fresh Cloudflare acceptance fixes for community transport, SPA deep links, server selection and access revocation. Instance and Server authorization boundaries remain local.
- A shared community rail in Shell and the direct client: horizontally centered Server icons, horizontal names, sign-in in the main area, and installation under the L4 menu.
- Consistent Instance terminology and entry points. The official `llll` Worker serves Landing, Shell, Docs and the Instance installer; the retired portal name is removed, and its production D1 is named `llll`.
- One protected main branch and a native Cloudflare Preview for each same-repository PR. Previews use `<preview-slug>.dev.llll.gg` with separate D1 data; production uses `llll.gg`. Both workers.dev URL settings stay disabled.
- Only a release PR that increases the shared version can publish llll, Server, Instance and Docs together. Production verifies and deploys the immutable released web archive; ordinary main merges leave the running version unchanged.
- Release provenance, complete artifact checksums, pinned Docs links, portable linux/amd64 runtime delivery and retry support for a published release whose production rollout has failed.

No database schema changes are introduced after the alpha.1 baselines. This fresh history has no upgrade path from the archived prototype. Existing customer Instances and Servers remain under their operators’ update control; publishing this release does not force their rollout.

Cloudflare is the first acceptance target. VPS/celld remains experimental; see [self-host findings](../self-host-findings.md). Native iOS/macOS distribution remains frozen. Optional mail, inference, calls and Telegram providers still need independent configuration and acceptance.
