# L4 0.2.0-alpha.2

This release simplifies adding a Server and fixes Cloudflare Workers Builds authorization in the installer.

- Use one `/create` page with Connect, Cloudflare and VPS tabs. The active plus button identifies the page, and the L4 logo stays on the current site origin, including PR Previews. Older `/open`, `/deploy` and `/servers` links redirect to the matching tab.
- Start customer Cloudflare Servers on their `workers.dev` address without a domain step. Keep connection and deployment fields when switching tabs, and remove saved connections directly from the Connect tab.
- Request `workers-ci.read` and `workers-ci.write` during Cloudflare authorization. Check access to deployment tokens before provisioning, with an explicit reconnect message for older grants. The OAuth application registration must allow both scopes; existing connections must reconnect to approve them.
- Carry the private first-owner claim automatically in the URL fragment into the Server setup flow. The installer email is reserved for that owner; finishing setup creates the owner account and signs it in. Server authorization remains local.

The `server-v1` schema lineage is unchanged. Existing customer Servers stay on their selected release until their operator updates them. Native iOS/macOS packaging remains frozen.
