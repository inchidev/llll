# L4 0.2.20

This release prevents a Container startup failure from permanently fencing a Factory Task before any workspace operation begins. Landing, Shell, installer, Server, portable runtime and Docs share **0.2.20**. Customer Servers update only when their operator chooses an update.

After a successful container reset, a failure to start the new container or complete its fixed readiness checks now produces a durable failed receipt. No source restore, user operation or checkpoint write has begun at that boundary. The last acknowledged checkpoint stays intact, the failed attempt counts against the Task budget, and a human may review a separate new operation. The failed action is never automatically replayed.

Receipt delivery can resume without starting the container again. A nonzero readiness-probe exit is now rejected. Reset failures, image-attestation failures, interrupted execution and uncertain checkpoint effects still fail closed and retain their uncertainty fence.

Existing uncertain actions, reviewed images and retained source are unchanged. Preserve or export acknowledged source and inspect the recorded outcome; updating does not replay or resolve an old uncertain action. The stdin bridge and chat reload protection from 0.2.19 remain included. Published artifacts are unchanged. No SQL or Durable Object migration is required.
