# L4 0.0.12

A Server on L4 Cloud can be made for a person by an AI agent or by a product built on L4, and claimed afterwards. This release adds one migration, `0007`, additive. Take the pre-update backup as usual.

## Software Factory

- **A Server that exists before anyone has set it up.** On L4 Cloud a Server can now be asked for by an agent, or made by a partner product for one of its accounts ([ADR 0012](https://github.com/inchidev/llll/blob/main/docs/adr/0012-server-creation.md)). The Server carries a seed from its creation: what the first claim creates besides the Owner. When the person claims through `/setup`, the claim page says that an Agent will be on the Server and under what name; the Agent is created by the new Owner under a **Cloud agent** Role (admin plus what an Agent needs to connect and work, since `admin` itself cannot connect over MCP), and the token the agent already holds is recorded for it, so the agent works on the Server the moment the claim lands, as an external Agent within its Role. A partner's Owner is created by the control plane instead, with a password nobody is told, and signs in from the partner's app through a one-time link at `/signin/link`, good for ten minutes. Members a partner names are linked by an explicit identity row, never by email. The Server keeps the partner's secrets and env encrypted for Projects the partner later creates, and takes a model provider key as **Server settings → Models** would. See [Choose how to run](https://llll.gg/docs/get-started/choose-how-to-run#l4-cloud-coming) and [External Agents](https://llll.gg/docs/agents/external-agents).
- **Discovery.** `GET /.well-known/llll` answers `"owner": true | false`, so an agent waiting on a new Server can see the claim land without credentials.

## Updating

- The update applies migration `0007`, which adds `server_setup.seed_json` and the table `member_identities`. It only adds; nothing is dropped.
- No binding or Durable Object changes. The relay `/.llll/cloud/*` gains actions that only a Server with `LLLL_RUNTIME=cloud` answers; every other Server keeps answering 404 there.
- Hosted Servers are not updated in place yet: the new relay actions reach only Servers created from this release or later.
