# L4 0.0.11

A Project can keep its repository inside L4, a Server can run its Agents' boxes on L4 Compute by the hour, and every tool call an Agent makes is authorized at one point. This release adds two migrations, `0005` and `0006`, both additive. Take the pre-update backup as usual.

## Software Factory

- **A repository inside L4.** A Project on a Server in your own Cloudflare account with Compute enabled can own its repository in L4, with no GitHub or Gitea account: **Connect repository → Create a repository in L4** on the Project page makes one in the Server's own storage, named after the Project, with `main` and a README, and attaches it. Agents work on it as on any repository; their branch is recorded on the Task as **Published for review**, the diff is on the Run, and a person merges from the Task. There is no pull request and no CI, and the Task says so before a merge. L4 itself keeps the branch rule, since the storage's tokens cannot, and does the merge with a token that never reaches a box. Under **Versions**, someone who may merge can release a version: a tag `v<version>` on `main`, listed on the Project page. On a VPS Server the option says it needs a Cloudflare-based Server; on L4 Cloud it is coming. See [ADR 0013](https://github.com/inchidev/llll/blob/main/docs/adr/0013-artifacts-git-provider.md) and [Repositories and code work](https://llll.gg/docs/agents/repositories#or-create-a-repository-in-l4).
- **L4 Compute.** The third place for a Task's box, next to your own VPS and your own Cloudflare account, on every Server. The Owner links the Server in **Server settings → Compute → Add L4 Compute** by signing in on llll.gg; the Server keeps only an encrypted Server token, and a Server on L4 Cloud is linked by construction. A Task's first turn asks llll.gg for a box of the Project's size (Small, Medium or Large, chosen on the Project page), the box pairs as a Node of its own and works like any Node with a durable disk, and it is released when the Task is Done, when the Owner releases it or when the Server is disconnected. Credit, this month's spend and the spend limit are shown as llll.gg reports them. When credit runs out the Task shows **Needs L4 Compute credit** with where to buy it, and nothing retries by itself; when llll.gg cannot be reached the page says so and nothing local is blocked. Prices are on [Pricing](https://llll.gg/pricing), never in the Server. See [Compute Nodes](https://llll.gg/docs/self-host/compute-nodes#l4-compute).

## Agents

- **One authorization point for every tool call.** Each tool an Agent calls, built in, outbound MCP or over the Server's own MCP endpoint, passes one rule table before its handler runs, and a refusal says why in plain words, for example that the delegating Reader cannot create tasks. Task tools count a Project policy the way the interface already did.
- **An external Agent is bound to its Run.** The webhook payload now carries `server.credential`, a credential for that Run alone. With it the Agent acts within its Role, no higher than the person who asked, their Agent access, the mandate and both Space boundaries, rechecked on every request, and it stops working when the Run closes, at its reply deadline or when access is revoked. A standing access token keeps working for work outside a Run. See [External Agents](https://llll.gg/docs/agents/external-agents) and [MCP](https://llll.gg/docs/agents/mcp).

## Updating

- The update applies migrations `0005`, which adds `project_releases`, and `0006`, which adds the `l4_compute_link` singleton, `compute_nodes.placement_id` and `box_id`, `compute_pairings.box_id` and the box's `cloud_*` columns on `factory_boxes`. Both only add; nothing is dropped.
- No binding or Durable Object changes. An L4 repository uses the Artifacts namespace Compute already provisioned; L4 Compute needs nothing on the Server beyond the link.
- The webhook payload keeps `version: 1`; `server.credential` is an added field.
