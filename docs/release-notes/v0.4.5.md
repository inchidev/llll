# L4 0.4.5

The deployment keeps its context: the shell on llll.gg now hosts the whole install journey instead of dropping it, and `/deploy` remembers what this browser created even after the one-hour Cloudflare authorization ends.

## Changes

- The rail's **Deploy** button opens the deploy flow inside the shell, so tracked installations stay visible while a new one deploys, and a finished deployment walks straight into the shell with its owner claim (`/open?installation=…&claim=…`) through the shell's query watcher.
- **Open in the shell** works from every navigation: the shell connects when `/open?installation=…` appears on any route change, shows an opening state, retries a freshly deployed installation once when it does not answer yet, and on failure keeps the address prefilled in the form with the reason above it.
- `/deploy` names an ended session: when the portal session is gone and this browser deployed before, it shows **Your deploy session ended** with **Reconnect Cloudflare** instead of silently looking like a first visit; completed installations are remembered per browser (`llll.deploy-recall.v1`) and listed on `/deploy` with **Open in the shell** links.
- The rail groups servers under an expandable installation header with a chevron, replacing the centered rotated tile; the **Add** and **Deploy** buttons carry labels and tooltips so they no longer read as duplicates.
- The `/.well-known/llll` connection check uses a 15s timeout and reports network failures directly; shell route matching tolerates trailing-slash URLs like `/deploy/`.
