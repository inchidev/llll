# L4 0.3.3

This release lets a Cloudflare Server manage its addresses, mail domains and Live with the Cloudflare access it keeps, and fixes calls that failed on every Cloudflare Server. Landing, Shell, installer, Server, portable runtime and Docs share **0.3.3**. It stays on the `server-v2` lineage with no new migrations, so a 0.3.x Server can update in place. Customer Servers update only when their operator chooses an update.

## Update from Settings

A Server that kept Cloudflare access in 0.3.2 updates to this release from Settings → Deployment → Updates, by itself. You can close the page while it runs.

## Without the installer

With Cloudflare access kept on the Server:

- **Server address:** add an address, make it primary or remove it directly in Settings.
- **Mail:** connect and disconnect mail domains in Settings → Mail. This sets up Cloudflare Email Routing and Email Sending for the domain.
- **Live:** connect using the Server's Cloudflare access; no separate API token is needed.
- The Server renews its Cloudflare access every week, so it keeps working between updates.

Moving files to R2 and setting up a compute node still use the official installer. Without kept access, everything works as before.

## Fixes

- ChatGPT sign-in, agent web search and Lizard calls failed on Cloudflare Servers because of an unsupported fetch option. They work again.
- Updating through the official installer opens its own page for that Server, without the create tabs.
