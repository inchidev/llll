# L4 0.4.6

The shell's two entry points share one screen, and the owner claim a deployment produced stays reachable no matter how the installation is opened again.

## Changes

- **One install screen**: the bare `/open` pane is replaced by the deploy screen — it starts with the address form that connects an existing installation, followed by the Cloudflare and VPS/Coolify creation flows, and no longer repeats the rail's logo.
- **Owner claim on re-entry**: the shell re-adopts the unused claim from the deploy session whenever an installation's page is about to mount fresh — the rail's sign-in tile, the address form, remembered "Open in the shell" links and reconnects — so **Private setup claim** is no longer empty outside the single post-deploy redirect.
- The rail's server tiles and the sign-in tile center under their installation header, matching the **Add** and **Deploy** buttons.
- On the connections page, the auth submit button (**Create owner** / **Create account** / **Sign in**) spans the full width on mobile.
- The deployment service names a missing `AUTH_SECRET` as a 503 instead of crashing, and the install screen stays quiet about it on instances where it is not configured.
