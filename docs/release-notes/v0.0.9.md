# L4 0.0.9

An Agent doing code work now lives on its Task's own box, with real Git, at the speed of the machine. Answers stream into the conversation as they are written. This release adds one migration, `0004`, and removes the per-command Factory without a transition: **Factory Tasks in progress, their workspaces and their pending actions are dropped by the update.** Finish or export that work first. Take the pre-update backup as usual.

## Agents

- **Answers stream.** A reply appears in the conversation while the Agent writes it, over the conversation's existing connection, for embedded Agents and boxes alike. Someone who opens the conversation mid-answer gets the text so far. The finished message is stored once, and notifications fire on it only.
- **The model's real limits.** A Run tells Pi its model's own context window and answer limit: what the provider reported when the model was added, then Pi's catalog, then 128,000 and 8,192 tokens for an unknown model, capped at 200,000 and 32,000. Agents used to forget after about 20,000 tokens and could not write a large file in one answer.
- **Long answers are posted whole.** An Agent's answer may be up to 12,000 characters. A longer answer used to stream and then disappear.

## Software Factory

- **One box per Task.** A Task's code work runs in one long-lived container with a Git checkout, on a VPS Node or as a Cloudflare container. The Agent uses Pi's own read, write, edit and shell tools there. Commands, tests, builds and commits make no request to the Server. On a VPS the box's disk stays until the Task is Done; on Cloudflare the work is checkpointed to Artifacts when a turn ends.
- **Parallel boxes.** A Node announces its CPU, memory and boxes, and the Server runs as many as fit, instead of one command per Node. A VPS Node runs one box per CPU while each gets 1 GiB, or `LLLL_NODE_BOXES`. A Cloudflare Node runs the number chosen at setup, 4 by default, which is also its containers' `max_instances`.
- **Publication is a Git push.** The Agent commits and calls `factory_publish` with the SHA. The commit is pushed to its own branch and the Task's draft pull request opens or updates. Binary files, lockfiles and large changes are ordinary commits. The old limits of 100 text files and 20 commits are gone. Review approves an exact commit SHA after reading its diff.
- **The mode gates what leaves the box.** Autonomous mode pushes on its own; plan mode needs one approved plan; review mode waits for a person on each push. Nothing asks about individual commands any more.
- **Network windows.** A box is closed by default. Each Project opens presets (npm, PyPI, crates.io, GitHub read) and its own hosts on the Project page, under Repositories. For anything else the Agent asks for a window: one host for up to eight hours, which waits for you in the Inbox.
- **Project secrets.** On the same page, enter a token once and bind it to its hosts. Nobody reads it back, Agents included. The Agent sees `L4_SECRET_<NAME>`, and the box's egress layer puts the value in only on a request to a bound host.
- **Git flow and merge from L4.** Each Project chooses who merges (a person, the Agent after checks pass, or a direct push to the base branch for experiments), the Agent's branch prefix and the merge method. A person merges from the Task, on the board or the Run's page, once every check of the head passed. If the repository reports no checks at all, a person can still merge and L4 says so. The Agent never merges unchecked code. Branch protection on GitHub or Gitea still decides.
- **Gitea pushes with Git.** Commits keep their SHA, and executable files are pushed as they are.
- **The per-command Factory is removed:** `factory_workspace`, its snapshot in the database, the proposal limits and the per-operation container.

## Updating

- The update applies migration `0004`. It adds `factory_boxes`, `factory_approvals` and `project_secrets` and the Project's Factory settings, and drops `factory_actions`, `factory_workspaces` and `agent_turns.draft_message_id`.
- Cloudflare: no binding or Durable Object changes. A Cloudflare compute node provisioned before this release keeps one box at a time until it is provisioned again from **Server settings → Compute → Server compute setup**.
- VPS installer: `sudo llll upgrade` also replaces the local Compute Node with this release's daemon and box image once the Server is healthy. The Node keeps its pairing and moves to protocol 2 as it starts, and the old per-command containers and volumes go. `sudo llll compute enable --trust-shared-kernel` does the same at any time, for example to retry; a failed replacement does not roll back the Server. The old workspace disks stay in `factory/state/workspace-disks` until you export them with `llll compute backup` and delete them with `llll compute release-old-disks --yes`.
- Other Docker Nodes: a Compute Node now speaks protocol 2. A Node of an earlier release gets no work and shows **Needs this release’s Compute Node** in **Server settings → Compute**. Stop it, disable and revoke it there, then pair this release's Node and box image.
