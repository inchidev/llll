# L4 0.0.14

L4 Cloud can update its hosted Servers in place, and a hosted Server's repositories run on L4 Compute without adding a computer. No migration.

## Software Factory

- **A repository in L4 runs on L4 Compute by itself on a hosted Server.** Creating a repository in L4 from a Project page, or connecting one, on a Server on L4 Cloud now attaches L4 Compute, the Server's own computer there, instead of asking to add one.

## Deployment

- **Updating a Server on L4 Cloud.** `updateHostedL4` in deployment-core moves a hosted Server to another published release in place: a D1 Time Travel bookmark of its database first, only the new migrations, the Client's files, the Worker with the release's bindings and only the Durable Object migrations past the script's own tag, then the new version verified at the Server's address. `restoreHostedDatabase` puts the database back at the bookmark. L4 Cloud uses it to update its Servers in batches, and to undo a failed update.

## Updating

- No migration and no binding change for a Server in your own Cloudflare account.
- A hosted Server made before 0.0.13 gains its Artifacts namespace binding with its first update.
