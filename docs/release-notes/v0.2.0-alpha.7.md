# L4 0.2.0-alpha.7

One common Docker Compose now runs a standalone Server in local development and on a VPS. This release adds the first pinned VPS installer and its backup, restore and upgrade commands.

- Share celld, private RustFS storage and a Caddy gateway between the prebuilt runtime, source build and development overrides. Only the gateway exposes host ports.
- Start local development with `pnpm dev:stack`: Client and Shell HMR, backend source reload, stable per-worktree credentials and persistent Server storage. A failed backend build keeps the previous completed build running.
- Publish `install.sh`, the matching `llll` CLI, exact Compose/Caddy files and the portable amd64 runtime through the immutable release workflow. Embed the identical installer at `https://llll.gg/install.sh`; unknown script/installer/JSON paths return 404 instead of landing HTML.
- Verify runtime and Compose checksums before installation changes. Generate private credentials once, preserve them on reruns, configure Caddy HTTPS for the operator's domain and print a claim link only for an unclaimed Server.
- Add `llll status`, `logs`, `start`, `stop`, `backup`, `restore`, `upgrade` and `uninstall`. Upgrades take a mandatory full-volume backup and restore old configuration, image and data after a failed startup. Restore preserves the original UUID and secrets. Uninstall retains backups and configuration; live volume deletion is explicit and scoped to the managed project.

The VPS installer targets Debian 12/13 and Ubuntu 22.04/24.04 on amd64. Prereleases require explicit `LLLL_CHANNEL=prerelease`. An operator-owned domain is required; ARM64 release publication, sslip.io fallback, automatic updates and scheduled backups are deferred. Local ARM64 development remains supported independently.

CI verifies installation of the prebuilt amd64 Server, owner setup, messages, private files, WebSocket transport, repeatable credentials and full-volume cold restore with the same UUID/session/message/file. Transaction tests cover tampered downloads, interrupted backup, downgrade refusal and rollback after persistent data mutation. **VPS/celld remains experimental:** fresh Debian/Ubuntu VM installation, public ACME/browser acceptance and real released N-to-N+1 upgrade/rollback remain scheduled for separate verification.

The official Shell/site updates through Workers Builds from this release's immutable archive. Existing standalone Servers remain pinned until their operator updates them. The `server-v1` schema lineage and Server-local authentication remain unchanged. Native iOS/macOS packaging remains frozen.
