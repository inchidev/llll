# L4 0.3.9

This release finishes the Coolify install: Coolify generates the first Owner's password, and the docs carry the Compose file to copy. Landing, Shell, installer, Server, portable runtime and Docs share **0.3.9**. It stays on the `server-v2` lineage and adds no migrations. The Server itself is unchanged from 0.3.8, so updating a Server is optional. Customer Servers update only when their operator chooses an update.

## Coolify

- The Coolify template sets `ADMIN_PASSWORD` from a generated `SERVICE_PASSWORD_ADMIN`. The first start creates the Owner, so you sign in with `ADMIN_EMAIL` and that password, with no setup claim. Change the password after you sign in. To choose it yourself, set `SERVICE_PASSWORD_ADMIN` (at least 12 characters) before the first deploy.
- [Run a Server on Coolify](https://llll.gg/docs/self-host/coolify) includes the whole Compose file with a Copy button, so you no longer need to open GitHub.

## Docs

- Copy buttons on code blocks are always visible on touch screens.

## Update to this release

A Cloudflare Server that keeps Cloudflare access updates from Server settings → Deployment → Updates by itself. A Docker Server updates by its image tag in Coolify or Docker Compose; the VPS installer uses `llll upgrade`. A Coolify service created from an earlier template keeps its own Compose file: to create the Owner without a claim, replace its `ADMIN_PASSWORD` line with `ADMIN_PASSWORD=$SERVICE_PASSWORD_ADMIN` before the first deploy.
