# Compute is the business

Amended on 2026-11-12: the product is now L4 Usage, of which Compute is one line (see the last amendment). Proposed on 2026-11-05, pricing section revised the same day from a flat worker to elastic hours, and the hour with a model inside added by invitation. Nothing here is built; prices are hypotheses to be checked against real use, and the published ones live only in `inchidev/llll-cloud`.

## Problem

L4 and Orbit (orbit.so, from the Coolify team) promise nearly the same workspace: chat, Tasks, documents, repositories, MCP, self-hosting and a Cloud. Orbit charges per workspace, Notion per block, Slack and Mattermost per seat and per call. If L4 charges for the workspace too, every feature Orbit adds is a feature L4 has to add, and the race never ends. A workspace feature takes a weekend to copy; a business model does not.

Agents in L4 already need somewhere to run code: a Compute Node that executes Task work in an isolated workspace and hands a draft pull request back to a person. Today three providers are wired by name into this repository: a Docker daemon on the operator's own Linux host, Cloudflare Containers on the operator's own account, and Lizard, whose sandboxes are created and billed through an API key the Owner enters in Server settings. The Lizard integration is about 560 lines in `workers/lizard-compute-do.ts`, `server/utils/lizard-*.ts` and `server/api/compute-providers/lizard/`, plus one environment flag in the Node daemon. It is in the public repository under the Elastic License, so "our provisioning is proprietary" is not yet true in code.

The earlier plan of a flat Cloud price per Server (and before it a Business key and per-Space plans) competes on the same table as Orbit. The Business key and the one-Space limit are already removed.

## Decision

**The workspace is free. L4 earns when agents work.** No price per Server, per Space, per person, per message, per history, per call or per feature, on L4 Cloud or on the operator's own infrastructure. The only thing sold is Managed Compute: machines L4 creates, runs, isolates, updates and bills for the customer, so that an Agent gets work done without anyone operating a box. The goal is the most parallel development a team can use, with L4 earning on every hour of it, so nothing in the price limits how many Agents work at once.

**Three ways to get compute, one Node protocol.** A Server knows one kind of machine: a Compute Node that pairs with a credential and polls for work (`claim`, `begin`, `heartbeat`, `result` in `server/utils/compute-nodes.ts`). Where the Node runs is the only difference:

- **Your own VPS.** The published `@llll/compute-node` daemon on a Linux Docker host the operator trusts. Free, no license limit on Nodes or parallel Runs; the operator installs, isolates and updates it. Any host counts: a home server, Hetzner, Kubernetes, or a sandbox the operator rents directly from Lizard or anyone else.
- **Your own Cloudflare.** Containers on the operator's Cloudflare account, as today. Free from L4; the operator pays Cloudflare.
- **L4 Compute.** Elastic: `llll-cloud` starts a microVM running the same published daemon for each Task that needs one, pairs it to the Server, and stops it when the Task's work is done. A hundred Agents get a hundred boxes. Paid by the hour of agent work, billed by the minute. A self-hosted Server buys it exactly like a Cloud Server: Server settings → Compute → Add L4 Compute, signing in with the llll.gg account. No API key field and no environment variable.

**What is source available and what is not.** This repository keeps the Node protocol, the daemon, the Cloudflare Containers path, the Server-side client that asks `llll-cloud` for a box, and the whole Task workspace, review and publication flow. It is complete on its own: an operator with one VPS has everything, and this daemon is the reference implementation for anyone who wants to run L4 work on other machines. `llll-cloud` holds provisioning (Lizard today, any provider tomorrow, behind one internal interface), per-tenant isolation, metering, billing and the fleet of boxes. There is no public Provider API and no third-party provisioner plug-in: the daemon is the open interface.

**Lizard leaves this repository.** The `lizard-*` files, the `compute-providers/lizard` routes, the `lizard` transport branch in `requireComputeNode`, the `provider: 'lizard'` capability and the daemon's `LLLL_COMPUTE_PROVIDER` flag go in one release, replaced by the L4 Compute client. A Node created by L4 Compute looks to the Server exactly like a VPS Node with a durable disk.

**Compute is sold by the hour of agent work, with a margin, and nothing else.** No subscription, no slot: a box per Task, billed by the minute while it runs, each run rounded up to the next minute with a one-minute minimum, in Small, Medium and Large sizes at different hourly prices. The provider bills us by the second, so the rounding is part of the margin and pays for boot time; rounding to the hour was considered and rejected, because a twenty-minute Task billed as an hour is the kind of trick the free workspace exists to get away from, and it would push teams to batch work instead of running it in parallel. The Owner sets a monthly spend limit and sees the running total. Lizard bills a Small microVM (2 vCPU, 4 GB) at about $0.0162 an hour by the second; a price of roughly three times cost, by the minute, is the starting hypothesis. Revenue then grows with the work Agents do: a small team with a thousand half-hour Tasks a month pays about $25 on $8 of cost, a shop running 10,000 hours pays about $500 on $162. A flat worker per month was considered and rejected: it caps parallelism, which is the thing L4 wants teams to do more of, and it makes the customer decide to buy before working. A reserved box at a discount may come later for teams that want a fixed bill; it is not part of this decision.

**The hour with a brain inside, by invitation first.** Hands alone are the public product. An agent hour can also include the model: a box plus inference, sold as one price per hour in brain sizes (Small, Medium, Large, by model class), each with a ceiling on tokens per minute. The ceiling is what makes a flat hour possible: a model emits only so many tokens an hour, so the worst case has a known cost, and a team running a hundred Agents in parallel pays a hundred hours, not an open bill. Inference goes through L4's own API keys with the providers, prepaid and under the same spend limit; never through consumer subscriptions, whose terms forbid sharing or resale, and whose loss would end the product. An Owner's own keys and a Member's own ChatGPT or Claude plan stay free, as today: then the hour is hands only. Because the margin on inference is thin and the cost per hour is unmeasured, hours with a brain open to our own teams and invited Servers first, and reach the public price list only after a month of measured tokens per hour per size. The public pages say nothing about them until then.

**Compute funds collaboration.** Each tenant's workspace costs on Cloud (D1, R2, Durable Object time, RealtimeKit minutes) are covered from a resource budget: a free base for every tenant plus a share of its Compute spend for the month, on the order of 10 to 15% as a starting hypothesis. The budget is computed monthly on our actual costs, not granted for life after one purchase. Its rules and the current usage are visible to the Owner; nothing is silently cut, deleted or blocked. Files and calls are the only costs large enough to need a ceiling for tenants who buy no Compute, and those ceilings are stated, not hidden.

The ceilings take one shape: a free base per Cloud Server plus a fixed increment per dollar of Compute spent in the month, one for files in gigabytes and one for call participant-minutes. Over the files ceiling, new uploads pause and nothing is deleted; over the calls ceiling, new calls wait for the next month. The numbers live only in `llll-cloud`, next to the prices. A Server on its own infrastructure has no ceilings: the storage and the calls are the operator's.

**Compute is prepaid credit in money, under a spend limit.** *(Superseded for accounts by the amendment below; partners keep it.)* Paddle's metering does not bill overage, so Compute is bought as credit (a prepaid balance in cents, never per hour pack), and each box run draws minutes times its size's price from that balance. The Owner sets a monthly spend limit; a box is not started when the limit or the balance is reached. A balance belongs to one Server and does not expire; refunds take back the same share. Hours as the unit of the ledger go, because sizes have different prices.

**Features stay off the strategy.** A feature enters the roadmap when it removes an obstacle for a real team using L4, not because Orbit shipped it, an announcement looked good, an agent could build it overnight or issues piled up.

## Amendment 2026-11-09: a Compute subscription per account

Decided with the owner after making the Lizard templates and reading how Lizard bills us. It replaces "Compute is prepaid credit in money" above for everything except partners; the workspace stays free, and nothing is priced per Server, Space, person, message or feature.

**L4 Compute is a subscription of an account: $19 a month, which includes $19 of Compute use.** Use is still priced by the minute of a box at its size's hourly price. Included use that a billing period does not spend expires at its end, so $19 is the least a paying account pays in a month; use beyond it is overage, billed after the fact by a one-time charge on the subscription (Paddle's `POST /subscriptions/{id}/charge`), at the end of the period or at once when it reaches $20, and never above the account's monthly limit. There is no free Compute and no trial: every minute of a box costs us money at Lizard, and a card on file is the barrier that keeps free boxes from mining and spam, as Lizard keeps its own.

**One wallet for all of an account's Servers.** The subscription belongs to the account, not to a Server, so a person with several Servers has one balance and one bill. A hosted Server is paid by the account that owns it on L4 Cloud; a Server on its own infrastructure linked to L4 Compute is paid by the account that linked it. The account sets a monthly limit on its total (by default $50) and may set a limit per Server. A box does not start without an active subscription, while a payment is past due, or at either limit; running boxes stop at the next hourly sweep, and no data is touched.

**Partners keep prepaid credit per Server.** A partner such as AfterPrompt pays L4 Cloud for its users' Servers by adding credit to a Server (ADR 0012's `credit/add`); that credit does not expire, and such a Server needs no subscription.

**Why not prepaid packs any more.** Paddle cannot bill metered overage by itself, which is why credit was prepaid; it can charge a subscription's card once for an amount we compute, which removes the reason. Packs made the buyer decide how much to buy before working and left credit stranded on one Server. Nothing had been sold under packs, so nothing moves.

**Lizard's ceiling.** Lizard's Pro plan runs at most 40 vCPU of sandboxes at once for the whole of L4 Cloud (20 Small boxes); its higher plans raise that. The plan has to grow with paying accounts before it is the limit.

## Amendment 2026-11-12: Usage, of which Compute is one line

Decided with the owner while folding PartyPortal into L4 as [Portal](0014-portal.md). Friends watching together, a consultant helping a client and a team on calls use files and video without ever starting a box; under the rules above they either hit a ceiling or cost L4 money with no way to pay for it. The reason for a free workspace still holds, so the line moves, not the principle.

**The take.** The workspace is free: L4 charges for no person, message, history, search, Space or feature. Those are bytes in a database, they cost almost nothing, and charging for them is a habit from the seat-priced era. L4 charges for what actually burns resources: machines for Agents, models, and gigabytes of files and video. Every Server gets a free base. A Server on the operator's own infrastructure is free entirely; they pay their own Cloudflare or VPS.

**L4 Usage replaces L4 Compute as the product.** It has one meter in money with one line per resource, each at our cost plus a convenience margin that the Pricing page states openly: box minutes by size (hands), later an hour with a model inside (brains) with things billed per item, such as generated images, on lines of their own, files above the base in gigabyte-months, call and Portal video above the base (participant minutes, relayed or fanned-out gigabytes), and mail if it acquires a real cost. Self-hosted, the same work costs the operator exactly their provider's price; on L4 Cloud it costs that price plus the margin for not operating anything.

**Two ways to pay, one meter.** The account subscription above stays and includes the same amount of Usage instead of Compute alone; overage, limits and the default account limit are unchanged. A prepaid balance in money, the partner credit above, becomes available to any account that prefers no subscription: a top-up is the "pack" for files, calls and Portal, drawn down by the same meter. A balance never expires and never pays a box beyond the spend limit.

**The free base no longer grows with Compute spend.** The per-dollar growth of the files and calls ceilings existed because files and calls could not be bought; now everything above the base draws from Usage. The base itself stays, now including Portal relay traffic, and its size lives in `llll-cloud` next to the prices.

**What does not change.** No price per Server, Space, person, message or feature, and no cap on how many Agents work at once. Direct peer-to-peer video in a Portal is free everywhere because it costs nobody anything. Prices and the base stay in `llll-cloud` only.

**Still to settle.** One margin for every line or one per line; how video is attributed to one tenant on L4 Cloud (one Realtime app per hosted Server is the likely answer, since Cloudflare reports usage per app); a warning before an account reaches its limit.

## Unknowns to settle before building billing

- **Hours and margin.** Run the real Tasks of two of our own teams through Managed Compute for a month and measure box hours per Task, hours per team per month, box start time and how much idle time a box keeps while an Agent waits for review. This sets the hourly price, the size defaults and whether a box is stopped between operations or kept for the Task.
- **Tokens per hour.** On the same Tasks, with inference through our keys, measure input, cached input and output tokens per agent hour for each model class, and the cost with and without prompt caching. This sets the brain sizes, their ceilings and whether a flat hour with a model inside holds at all. Public estimates from list prices put a fully busy hour at about a dollar on a small model and tens of dollars on the largest; they are estimates, not data.
- **Inference terms.** Which providers offer zero data retention on the API and a data processing agreement we can pass to customers, since their code and conversations go through us when they choose a brain.
- **Provider interface in `llll-cloud`.** Lizard is first; Cloudflare Containers or Sandboxes in our own account and a plain VM pool must fit the same interface without the Server noticing.
- **Pairing handoff.** How `llll-cloud` pairs a box to a Server it does not operate, many times a day: the Server asks for a box for one Task and receives Node credentials, or issues a pairing token the box redeems. Either way a box's credential is scoped to one Server, ends with its Task, and is revocable from both sides. The Server also needs a spend limit check before asking for a box.
- **Resource budget arithmetic.** Actual D1, R2, DO and RealtimeKit costs of a small active tenant, measured, before choosing the base budget and the share.
- **Cloudflare credits.** L4 runs on Workers, D1, R2 and Durable Objects, so Cloudflare for Startups credits and Workers Launchpad are worth applying for; they would cover free tenants and the Workers for Platforms base fee in the first year. Terms and deadlines on their pages disagree and must be checked at application time.

## Consequences

- **Server settings → Compute shows three choices** and nothing provider-specific beyond them. The Lizard key field is gone. An operator who wants Lizard directly rents a sandbox there and installs the daemon: it is a VPS to the Server.
- **One release removes Lizard** from `inchidev/llll`. Servers that paired Lizard Nodes through the old routes lose them on update; this is accepted, nothing of it has customers yet.
- **`llll-cloud` grows a second product**, L4 Compute, with its own catalogue entry, Paddle product, a seconds ledger and a fleet of short-lived microVMs. Its existing prepaid compute hours and seconds ledger fit this model and stay; only the paid Cloud plan goes. Billing stays per Server as in [ADR 0008](0008-server-per-tenant.md), but the Cloud plan itself is free.
- **Pricing and landing in `llll-cloud` change**: no price per Server; the pitch is a free workspace where you pay for the hours your Agents work, by the minute, with no limit on how many work at once. The Docs here keep linking to Pricing and never quote numbers.
- **Isolation is per tenant by construction.** Managed boxes are Firecracker microVMs with their own kernel, one Task of one Server each. The shared-kernel Docker path stays what [Compute nodes and Task workspaces](../software-factory.md) says it is: for the operator's own trusted code, never resold.
- **The Docker daemon stays complete in the open**, so a self-hosted L4 with its own machines is a full product, and the free product is the funnel for Managed Compute, not a crippled copy of it.
- **Supersedes** the flat Cloud price per Server and the Business key as revenue. Models keep running on the customer's own keys or subscription by default and for free; the hour with a brain inside is an addition for those who want one bill, not a replacement.
- **Rejected: a pool of consumer subscriptions** (many Codex or Claude plans) working customers' Tasks at plan prices. It violates the providers' terms, it would be shut down without notice, and it would take every customer's running work with it. Inference is bought from the API or not at all.
